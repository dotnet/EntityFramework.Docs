# Breaking changes in EF Core 12 (EF12)

This page documents API and behavior changes that have the potential to break existing applications updating from EF Core 11 to EF Core 12. Make sure to review earlier breaking changes if updating from an earlier version of EF Core:

- [Breaking changes in EF Core 11](xref:core/what-is-new/ef-core-11.0/breaking-changes)
- [Breaking changes in EF Core 10](xref:core/what-is-new/ef-core-10.0/breaking-changes)
- [Breaking changes in EF Core 9](xref:core/what-is-new/ef-core-9.0/breaking-changes)
- [Breaking changes in EF Core 8](xref:core/what-is-new/ef-core-8.0/breaking-changes)

## Low-impact changes

<a name="fromsql-duplicate-parameter-names"></a>

### `FromSql` and `SqlQuery` now throw for same-named `DbParameter`s that are referenced by name in the SQL

[Tracking Issue #32932](https://github.com/dotnet/efcore/issues/32932)

#### Old behavior

When the same query contained more than one `DbParameter` with the same name, EF Core renamed the later parameters so that every parameter sent to the database had a unique name. This is only correct when the SQL refers to the parameters positionally (for example `{0}`), because EF Core then writes the new name into the SQL.

When the SQL referred to a parameter by the name written in the SQL text, the SQL was not changed, so it kept referring to the first parameter with that name. For example, in the following query both subqueries use `@date`, and both therefore used the value of the first parameter:

```csharp
var result = await Enumerable
    .Range(1, 2)
    .Select(index => context
        .Set<TestEntity>()
        .FromSqlRaw(
            "SELECT @date AS Date",
            new SqlParameter("date", new DateOnly(2024, 1, index))))
    .Aggregate(Queryable.Union)
    .ToListAsync();
```

This returned only `2024-01-01` instead of both `2024-01-01` and `2024-01-02`. No error was reported. If the parameters happened to have equal values, the query returned the expected results.

#### New behavior

Starting with EF Core 12, an <xref:System.InvalidOperationException> is thrown when a `DbParameter` would need to be renamed because another parameter in the same query has the same name, and the SQL passed to `FromSqlRaw` or `SqlQueryRaw` does not refer to that parameter positionally. This also applies when the parameters have equal values, and when the name conflicts with a parameter name generated by EF Core, such as `p0`.

Queries that refer to every parameter positionally, or that use a distinct name for each parameter, are not affected. `FromSql` and `SqlQuery` with interpolated strings always use positional parameters, and are not affected.

#### Why

EF Core cannot change parameter names that are written directly in the SQL, so the query could not be made to use the right value for each parameter. Returning wrong results without any error is much worse than throwing, and it was not possible to reliably tell whether the SQL was correct when the parameter values were equal.

#### Mitigations

Use a distinct name for each parameter:

```csharp
var query1 = context
    .Set<TestEntity>()
    .FromSqlRaw("SELECT @date1 AS Date", new SqlParameter("date1", new DateOnly(2024, 1, 1)));

var query2 = context
    .Set<TestEntity>()
    .FromSqlRaw("SELECT @date2 AS Date", new SqlParameter("date2", new DateOnly(2024, 1, 2)));

var result = await query1.Union(query2).ToListAsync();
```

Or, in particular when the queries are generated dynamically, refer to the parameters positionally, which allows EF Core to give each one a unique name:

```csharp
var result = await Enumerable
    .Range(1, 2)
    .Select(index => context
        .Set<TestEntity>()
        .FromSqlRaw(
            "SELECT {0} AS Date",
            new SqlParameter("date", new DateOnly(2024, 1, index))))
    .Aggregate(Queryable.Union)
    .ToListAsync();
```

If the values are plain values rather than `DbParameter` instances, pass them directly (for example `FromSqlRaw("SELECT {0} AS Date", new DateOnly(2024, 1, index))`) or use `FromSqlInterpolated`, in which case EF Core creates and names the parameters.
